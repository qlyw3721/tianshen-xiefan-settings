# 「XX 人物志」自动化工作流程 v1.2

> 触发条件：用户说「**启动XX人物志**」（唯一启动口令；不带「启动」二字者**完全等价**）。
> 适用范围：主要人物（§3.1）、重要配角（§3.14／§3.7 A 组）；其余角色走简版。
> 制度依据：设定集 **§0.6 第二十三款**（六步流程）＋**第二十七款**（本工作流）＋**第二十八款**（启动口令与两段式确认）；本文件是它们的**可执行版**，冲突时以 §0.6 为准。
> 推导方法：`01_推导范式.md`（六算子＋反面清单＋验收五问，**带版本号，每轮迭代**）。
> 首例：圣阿尔忒弥斯（v2.01）→ 莱茵哈泰（v2.02）→ 迦卡妙（v2.03）→ 卡妙女皇（v2.04/v2.05）。

---

## 零、两条铁律

**第一条·人物志不是复述原文，是把原文事实推到「可续写的产出层」。**
原文事实层（已归位的不重抄）＋产出层（性格／走向／终局／五维／伏笔／原型）＋待裁清单（交用户定夺）。

**第二条·裁定与落盘是两次确认，不是一次。**
用户对推导内容的「裁定」（选 a/b、认可某项）**不等于**授权写进设定集。必须再等用户明确说「添加进设定集」「确认」「落盘」之类，才可进入第 6 步。
**默认行为：交出推导与待裁清单后停下，不主动落盘。**

**不冒充原文**：任何标【原创】的东西，都不得写成叙述事实；任何标【原文】的东西，必须带可复核行号。

## 零之一、两个口令（v1.2 合并后只剩两档）

| 口令 | 授权范围 | 不授权 |
|---|---|---|
| 「**启动XX人物志**」（唯一启动口令；「XX人物志」「做个 XX 的人物志」「补 XX 的人物志」等**完全等价**，直接交付人物 docx 素材同效） | 启动全流程，跑到第 5 步交裁定 | 落盘 |
| 「**添加进设定集**」「确认」「落盘」 | 授权第 6 步落盘，**仅限已裁定范围** | 改动用户未裁定过的项 |

**v1.2 变更**：用户裁定「『XX人物志』和『启动XX人物志』是一个意思，口令合并，授权内容也合并」——v1.1 的「提及即启动／显式启动」两分法与三档授权**作废**，合并为上表两档。

**例外**：用户在同一句里既启动又预授权（如「启动XX人物志，推导完直接落盘」），则依用户明示执行，但**交裁定这一步的展示不可省略**——必须把全部原创项列清，只是不再等回复。

## 一、六步流程（每步有命令、有产出、有门禁）

### 第 1 步 · 取批（Pick）

```bash
python _rzz.py pick "人物名" "别名1" "别名2"
```

产出：`人物志工作流/取批/<人物名>_取批单.md`

取批单含四块，缺一不可：
1. **原文命中清单**——前后传每一处命中（行号＋原句），这是本轮的素材边界；
2. **频次与分布**——前传 N 处／后传 M 处，判断是「主线人物」还是「一闪而过」；
3. **设定集存量**——§3.1／§3.13／§1.7／§3.16 已有哪些条目，**先查重，防重复添加**（用户已多次要求确认在库，这一栏就是答案）；
4. **是否已有补注块**——`#### vX.XX 补注｜「人物名」` 是否存在。已存在则默认「已有项不重写」，只补新增。

> **门禁**：命中 < 5 行且无用户素材 → 先向用户索要素材（docx／理解长文），不要硬推。

### 第 2 步 · 精读（Read）

逐条读命中行，**不跳读、不靠印象**。读的时候只做一件事：把「可直接引用的事实」抄成行号清单。

> **门禁**：凡是打算写进推导的每一句原文引语，必须在这一步抄下来并核对行号。后面第 3 步会再核一遍。

### 第 3 步 · 回查原文（Verify）——**最容易被跳过、也最容易翻车的一步**

对第 2 步抄下的**每一条**行号，重新打开原文定位确认：
- 行号对不对（**必须带上下文核，禁止对行号做全局数字替换**——v2.04 的教训）；
- 引语是否逐字（异体字、漏字、"朕/我"这类人称差异要单列）；
- 说话人是谁（v2.04 抓到「拒绝做神的玩偶」被误归奥古斯丁，实为卡妙女皇）；
- 同一句话在前传／后传是否重出（两稿异文按「天神下凡 ＞ 宗教裁判所」处理）。

产出：**原文核验表**（模板 `02_原文核验表模板.md`），三列：引语｜行号｜核验状态（✅逐字／⚠️转述差异／❌误归）。

> **门禁**：核验表里出现 ❌ 的，必须当场修正认知，再往下走。

### 第 4 步 · 推导（Derive）

**先读 `01_推导范式.md`**，按六算子走：主轴（一个动词）→ 代价（获得必付）→ 反推（从果推因）→ 说话人定位（三档）→ 空白判定（四级）→ 链条（原型推制度）。出稿前用**验收五问**自检。

按模板 `03_推导稿模板.md` 出稿，七块：

| 块 | 内容 | 标注 |
|---|---|---|
| ① 原文锚 | 人物骨架的硬证据（行号＋引语） | 【原文】 |
| ② 内在逻辑 | 一条主轴＋若干代价/机制，解释"为什么是他/她" | 【原创推导】 |
| ③ 三项 | 性格刻画／剧情走向设计／终局命运预测 | 原文优先，缺则【续补·原创·待裁】 |
| ④ 五维 | 性格外貌／说话方式／与主角走向／最终命运／冲突终裁 | 承 v1.68 规则四 |
| ⑤ 伏笔 | 只给线索、不揭盖（附"读者能推得、角色不可说破"红线） | 【原创·待裁】 |
| ⑥ 原型 | 现实原型与分层（国家/族群/个人可各有一套） | 【用户裁定】或【原型参照】 |
| ⑦ 防误判 | 每条"不能这么写" | 强制 |

**写内在逻辑的方法**：不要罗列特征，要找**一个动词**——他/她一生在做什么。卡妙女皇是"用最冷的手做最热的事"，巫婆是"用鞭子让人仰视、用阳光让人不冷"。找到这个动词，三项和伏笔自然长出来。

### 第 5 步 · 交裁定（Defer）——**默认停在这里**

**结论先在对话里给，不动正文。** 附一张待裁清单，3–5 条，每条给：
- 问题是什么；
- 我建议哪个（并说明理由）；
- 各选项的后果差异。

**两段式确认（v1.1 新增，用户 2026-11-19 明令）**：

```
第 5 步 交裁定  →  用户【裁定】内容（选 a/b、认可/否决某项）
                →  用户【确认】落盘（"添加进设定集"/"确认"/"落盘"）
                →  才进第 6 步
```

裁定之后若用户未说落盘，**只做两件事**：把裁定结果整理成清单复述一遍、问「是否按此落盘」。不得自行判断「他都说可以了那就写吧」。

> **门禁**：① 用户未裁定 → 一个字不许落进设定集；② 用户已裁定但未确认落盘 → **同样不许落盘**；③ 落盘内容不得超出用户裁定的范围（想加别的，另开一轮）。

### 第 6 步 · 归位＋收口（Land）

用户裁定后：

```bash
python _v2XX_apply.py          # 落盘脚本（rep/ins 全唯一断言）
python _rzz.py check           # 收口自检（preflight/verify/CRLF/表格/docx 同步）
```

固定落点（8–12 块，按实际取舍）：

| # | 落点 | 内容 |
|---|---|---|
| 1 | 顶部戳 | 版本＋轮次＋一句话摘要 |
| 2 | 修订记录 | 本轮裁定逐条（倒序插在最前） |
| 3 | §0.6 | 新增「第 N 款」裁定指针（历史款只加补记，不改原字） |
| 4 | §3.1／§3.14 | 人物条目行末加 `**vX.XX 注**` |
| 5 | §1.7 | 名言入表（有新名言时） |
| 6 | §3.16 | **深化补注块**（本轮主体，七块齐全） |
| 7 | §14 | 时间线／国家事件（涉年份时） |
| 8 | §11.1 | 登记（写清：素材行号／裁定项／落点／边界） |
| 9 | 台账 | A 区裁定／B 区原创／纠错档案 |
| 10 | MEMORY | 规则层 #N＋状态行；项目层简版 |
| 11 | 日志 | 当日日志新增一节 |
| 12 | Git | commit＋push |

**收口顺序不可颠倒**：改 md → 跑脚本落盘 → check → 切 `_md2docx.py` 三处版本号 → 重生 docx → 再 check → 台账（先改工作副本→cp 规则层→双份验证）→ MEMORY → 日志 → Git。

## 二、交裁定的固定五问

每轮人物志，主动把这五条摆到用户面前（有则答、无则标"不涉"）：

1. **终局**——这个人怎么死/怎么退场？原文给了没有？没给的话，是留白还是补？
2. **与主角的关系定性**——是爱情线、镜像、师徒、对手，还是"非爱情但深度纠缠"？（红线：禁男女关系明写）
3. **称号/名字**——原文有无？无则原创，并给语源。
4. **是否入后记史实层**——若涉及"多年以后"，一律标后记层、不入主线（841 红线）。
5. **原型**——现实原型是什么？国家层/族群层/个人层是否各有一套？

## 三、红线（承 §0.6 第二十三款⑤）

- 禁男女关系明写；动情只留白。
- 「征服 ≠ 超越」。
- 当世第一强者人设不变。
- 主线剧情 ≤ 神圣历 841 年；后记层不得混入主线。
- 既有终局名单不冲突。
